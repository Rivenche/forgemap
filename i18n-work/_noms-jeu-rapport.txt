Methode
1. Traductions : TextAssets 'localization*' de resources.assets (CSV, une colonne par langue).
   Fichiers lus (jetons ajoutes) : {'localization.csv': 5570, 'localization_ashlands.csv': 0, 'localization_captions.csv': 142, 'localization_celebrationupdate.csv': 0, 'localization_combatupdate.csv': 0, 'localization_deepnorth.csv': 0, 'localization_extra.csv': 15, 'localization_warriortitles.csv': 202, 'localization_witch.csv': 0} ; variantes consoles (xbox/ps/switch/platformspecific) ignorees. Fichier principal prioritaire.
   5929 jetons au total.
2. Prefab -> jeton : 799 bundles de StreamingAssets/SoftRef/Bundles (typetrees embarques).
   MonoBehaviour avec m_itemData (ItemDrop) -> m_itemData.m_shared.m_name ;
   avec m_faction+m_boss+m_name (Character/Humanoid) -> m_name ; avec m_resources+m_category+m_name (Piece) -> m_name.
   Nom du prefab = m_Name du GameObject ; seuls les objets racines (Transform sans parent) sont gardes,
   ce qui ecarte les copies placees dans les lieux (ex. 'wood_beam (3)').
   Si un prefab a plusieurs composants : priorite objet > creature > piece (ex. MeadHealthMedium = objet).

Limites
- Seuls ItemDrop, Character et Piece sont couverts (pas Pickable, MineRock, Destructible, lieux...).
- Quelques prefabs internes/de test peuvent figurer (tout objet racine portant ces composants).
- Noms composes (Upgrader*, SnowballBig...) : jetons remplaces un par un comme le fait le jeu, d'ou un francais parfois maladroit (ex. 'Big Boule de neige', 'Argent Combat Idole').
- Les textes peuvent contenir des balises de mise en forme du jeu telles quelles.
